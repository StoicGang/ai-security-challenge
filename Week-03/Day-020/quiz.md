1. Explain the fundamental difference between an LLM generating a standard natural-language response and an LLM generating a function (tool) call. What is the model actually outputting when it decides to use a tool?
> When generating a standard natural-language response, the LLM relies solely on its internal pre-trained weights to predict text for the user. However, when generating a function call, the LLM outputs a structured data object (typically JSON) containing the specific name of the tool to execute and the exact parameters required. Instead of answering the user directly, the model pauses its natural language generation and communicates strict instructions back to the application, delegating tasks it cannot reliably perform itself (such as fetching real-time data or executing exact mathematics).

2. In the ReAct (Reason + Act) agent loop, the LLM doesn't just call a tool and immediately answer the user. Explain the sequence of steps that occur in a full "Reason, Act, Observe" cycle from the moment the user submits a prompt.
> The ReAct loop is an iterative process of reasoning and acting. First, in the Reason phase, the LLM analyzes the user's prompt and decides it needs external data, requests a structured tool call. Next is the Act phase, where the Python application intercepts this request, executes the actual code, and captures the output. Finally, in the Observe phase, the application feeds the raw tool output back to the LLM. The LLM evaluates this new information. If the result satisfies the user's query, it synthesizes a final natural-language response. If the information is incomplete, the LLM reasons again and triggers another tool call, repeating the loop until it has enough context to answer.

3. Why is relying on a System Prompt (e.g., instructing the LLM "Only read approved files, do not access system files") considered a major security vulnerability? How does enforcing the Principle of Least Privilege in the tool's execution code eliminate this risk?
> Relying on a system prompt for security is essentially asking the LLM nicely not to do something. Because LLMs are probabilistic, system prompts aren't hard walls a clever user can bypass them using prompt injection or jailbreaks. If your Python tool has full read access to the system, a bypassed prompt means game over. Enforcing least privilege directly in the Python code fixes this because code is deterministic, not probabilistic. If the Python function hardcodes the file path or checks that the request stays inside an approved folder, the model physically cannot read unauthorized files—no matter how clever the prompt injection is. You're moving security out of a suggestive system prompt and into an unyielding line of code.

4. Let's say you build an agent and give it two tools: a calculator and a file reader. When a user asks a question, how exactly does the LLM know which tool to pick? What specific information is it relying on to make that decision?
> When we pass tools to an LLM, we aren't giving it our Python code we're handing it a JSON object containing the tool's name, the parameters it requires, and a plain-English description of what it does.The LLM essentially acts as a router. When the user asks a question, the LLM reads through those tool descriptions and does a semantic match against the user's intent. If the description for the calculator says "Use this to evaluate math expressions," and the user asks "What is 5 times 5?", the model connects the dots, picks the calculator, and structures the parameters to match your schema.
