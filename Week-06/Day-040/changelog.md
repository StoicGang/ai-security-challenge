# Verified Fix Changelog

In Week 4, the agent's tool-call activity was not observable from its normal output, so we could see the final response but could not trace which tools the model called or what inputs it provided to them during execution. The change made in Day 039 was to add runtime logging that prints the tool name and its input whenever the agent produces a tool-call step. This was verified by running a complex query that triggered multiple tool calls and capturing the resulting terminal output, which showed the expected tool names and their inputs before the final agent response. This demonstrates that tool-call activity is now observable during execution, although the current implementation is not yet a persistent audit system with historical logs, timestamps, or session tracking.
